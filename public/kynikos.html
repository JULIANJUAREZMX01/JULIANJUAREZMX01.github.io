Requisitos: Windows 10 u 11, 8 GB de RAM (16 ideal), 6 GB libres.

Todo en un bloque

cd $HOME\Documents
git clone https://github.com/JULIANJUAREZMX01/KynicOS.git
cd KynicOS
.\nodo\arranque-todo-en-uno.ps1

Hace los cinco pasos: Git, repositorio, instalador, revisión de configuración y comprobación del bot. Si falta un valor en el .env, se detiene y te dice cuál.

Paso por paso, si prefieres verlo

1. Git. Si dice que no se reconoce el comando, instálalo y reabre la terminal.

git --version
winget install --id Git.Git -e --source winget

2. Repositorio. Queda en Documentos\KynicOS.

cd $HOME\Documents
git clone https://github.com/JULIANJUAREZMX01/KynicOS.git
cd KynicOS

3. Instalador. Instala Python y Ollama si faltan, descarga el modelo (4.7 GB, una sola vez) y crea el .env pidiéndote el token sin mostrarlo.

.\nodo\instalar.ps1

Si Windows bloquea el script por política de ejecución, se relaja solo para esa ventana:

Set-ExecutionPolicy -Scope Process -Bypass -Force
.\nodo\instalar.ps1

4. Arrancar. La ventana se queda ocupada: mientras esté abierta, el bot está vivo.

.\.venv\Scripts\python.exe cli\kynikos.py run

5. Diagnóstico desde otra terminal, con el nodo corriendo:

.\.venv\Scripts\python.exe cli\kynikos.py doctor
.\.venv\Scripts\python.exe cli\kynikos.py telegram
.\.venv\Scripts\python.exe cli\kynikos.py doble-paso estado

Qué significa cada variable del .env

VariablePara qué sirve
TELEGRAM_TOKENCredencial del bot. Sin ella no hay canal.
TELEGRAM_USER_IDSolo ese usuario puede hablarle. Es el candado.
PERSONATono y reglas con que responde.
OLLAMA_MODELModelo local. qwen2.5:7b es el que va fluido en CPU.
OLLAMA_NUM_CTXCuánta conversación recuerda a la vez.
MAX_TOKENS_SALIDATope de largo por respuesta.
TIMEOUT_LLMPaciencia en segundos. En CPU hace falta holgura.
KYNIKOS_PALABRA_1La palabra que abre el doble paso.
KYNIKOS_ESTADO_DIRDónde guarda el estado del doble paso.

Se edita con notepad .env. Nunca se pega en un chat ni se sube a GitHub: ya está en .gitignore.

Dejarlo arrancando solo

$repo = "$HOME\Documents\KynicOS"
$accion = New-ScheduledTaskAction -Execute "$repo\.venv\Scripts\python.exe" -Argument "cli\kynikos.py run" -WorkingDirectory $repo
$disparo = New-ScheduledTaskTrigger -AtLogOn
Register-ScheduledTask -TaskName "KYNIKOS nodo" -Action $accion -Trigger $disparo -Force
Start-ScheduledTask -TaskName "KYNIKOS nodo"

Lo que no se hace nunca

  1. Pegar el token o la palabra del primer paso en un chat, issue o captura.
  2. Subir el .env a GitHub.
  3. Repartir el enlace del bot. El candado por ID ayuda, pero el enlace no se comparte.
  4. Instalarlo en un equipo de un tercero: quien sea dueño de la máquina puede leer el .env.

Actualizar (solo después de instalar)

No lo corras antes de haber instalado. Si lo haces verás ObjectNotFound: .\.venv\Scripts\python.exe: significa que todavía no existe el entorno de Python y que falta ejecutar el instalador completo.

cd $HOME\Documents\KynicOS
git pull
.\.venv\Scripts\python.exe -m pip install -q -r requirements-bot.txt
