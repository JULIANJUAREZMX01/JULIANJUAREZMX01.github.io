KYNIKOS · arranque en Windows

Nodo primario en tu PC · sin administrador · sin costo · verificado el 3 de noviembre de 2026

Antes de empezar

Ten a mano dos datos: el token de @BotFather (/mybots → kynicOS_robot → API Token) y una palabra secreta que inventes. El script te las pedirá en el bloque 2.

Windows 10 u 11, 8 GB de RAM (16 ideal), 6 GB libres. Sin administrador y sin costo.

Bloque 1 · Traer el repositorio

cd $HOME\Documents
git clone https://github.com/JULIANJUAREZMX01/KynicOS.git
cd KynicOS

Debe aparecer un mensaje de clonación y nada en rojo. Si git no se reconoce: winget install --id Git.Git -e --source winget, cierra la ventana, abre otra y repite.

Bloque 2 · Instalar, arrancar y validar

cd $HOME\Documents\KynicOS
Set-ExecutionPolicy -Scope Process -Bypass -Force
.\nodo\arrancar-y-validar.ps1

Debe terminar así:

OK   VALIDADO: el nodo está escuchando a Telegram.

No es un adorno: consulta la API de Telegram y espera el error de conflicto, que solo ocurre si el nodo ocupa el canal. Si no lo recibe, dice FALLO.

Si se detiene diciendoQué hacer
Falta: git / python / ollamaCorre el winget install que te muestra, cierra la ventana, abre otra y repite
El proceso murió al arrancarEl script imprime el error real debajo
Telegram no reporta que alguien escucheEl token del .env no es el de @kynicOS_robot. Corrige con notepad .env

El token no se muestra al pegarlo: es normal, pégalo con clic derecho y Enter. Tarda por la descarga del modelo (4.7 GB).

Bloque 3 · Probar en Telegram

/estado

Escríbelo en @kynicOS_robot. Si contesta, el nodo está operativo. Después: una frase normal (debe responder) y tu palabra secreta (debe llegar una sola notificación con Autorizar y Rechazar).

Qué significa cada variable del .env

VariablePara qué sirve
TELEGRAM_TOKENCredencial del bot. Sin ella no hay canal.
TELEGRAM_USER_IDSolo ese usuario puede hablarle. Es el candado.
PERSONATono y reglas con que responde.
OLLAMA_MODELModelo local. qwen2.5:7b es el que va fluido en CPU.
OLLAMA_NUM_CTXCuánta conversación recuerda a la vez.
MAX_TOKENS_SALIDATope de largo por respuesta.
TIMEOUT_LLMPaciencia en segundos. En CPU hace falta holgura.
KYNIKOS_PALABRA_1La palabra que abre el doble paso.
KYNIKOS_ESTADO_DIRDónde guarda el estado del doble paso.

Se edita con notepad .env. Nunca se pega en un chat ni se sube a GitHub: ya está en .gitignore.

Bloque 4 · Que arranque solo (opcional)

cd $HOME\Documents\KynicOS
.\nodo\registrar-tarea.ps1

Solo después de que el bloque 3 conteste. Comprueba que el proceso esté vivo; no se fía del estado Ready de Windows, que solo significa "registrada".

# detener el nodo
Stop-Process -Id (Get-Content $HOME\Documents\KynicOS\.kynikos\nodo.pid)

# quitarlo del arranque automático
Unregister-ScheduledTask -TaskName "KYNIKOS nodo" -Confirm:$false

Problemas comunes

SíntomaArreglo

ObjectNotFound: .\.venv\Scripts\python.exeEl entorno aún no existe: ejecuta .\nodo\instalar.ps1 completo antes que nada
Recibe pero no contestaEl nodo no está corriendo: paso 4, con la ventana abierta
401 o UnauthorizedToken mal copiado: sin comillas ni espacios, edita .env
Respuestas lentasUsa 7B. El 14B baja a ~3 tokens por segundo en este equipo
can't use getUpdates with webhook activecurl "https://api.telegram.org/bot<TU_TOKEN>/deleteWebhook"
No llega la notificación del doble pasoEscribe /start en @kynicOS_robot una vez

Lo que no se hace nunca

  1. Pegar el token o la palabra del primer paso en un chat, issue o captura.
  2. Subir el .env a GitHub.
  3. Repartir el enlace del bot. El candado por ID ayuda, pero el enlace no se comparte.
  4. Instalarlo en un equipo de un tercero: quien sea dueño de la máquina puede leer el .env.

Actualizar el código

No lo corras antes de haber instalado. Si lo haces verás ObjectNotFound: .\.venv\Scripts\python.exe: significa que todavía no existe el entorno de Python y que falta ejecutar el instalador completo.

cd $HOME\Documents\KynicOS
git pull
.\.venv\Scripts\python.exe -m pip install -q -r requirements-bot.txt
